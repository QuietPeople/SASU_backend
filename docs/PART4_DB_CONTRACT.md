# 파트 4 DB와 통계 연결 기준

기준: 2026-10-22 첨부 SASU_backend-main-2, 0001_initial_schema. 새 테이블·컬럼·마이그레이션 없이 기존 구조를 사용한다. 원본 기록을 만드는 파트 1~3이 아래 저장 계약을 지키는 것을 전제로 한다.

## 기록과 잠금

- 외부 record_generation 0은 DB learning_epoch 1이다. 외부 값에 1을 더해 비교하고 반환할 때 1을 뺀다.
- 기록 변경은 user_settings 행을 먼저 FOR UPDATE로 잠근 뒤 현재 세대를 비교한다. 삭제 요청도 검사한다. 현재 likes와 reset 구현이 이 순서를 사용한다.
- 필요한 콘텐츠·문항 잠금은 사용자 상태 잠금 다음에 취득하고 여러 콘텐츠는 ID 오름차순으로 처리한다. 커리큘럼 편성은 커리큘럼 행을 먼저 잠그고 콘텐츠를 ID 순서로 잠그며 사용자 기록을 변경하지 않는다.
- quiz_attempts 생성만으로 노출 수를 올리지 않는다. 실제 화면 표시가 확인된 QUIZ_DISPLAYED와 attempt_id가 있어야 한다. 노출 중복은 DB 고유 인덱스로 제한한다.
- 답변은 quiz_responses에 저장하고 오답 상태는 DB 트리거가 반영한다. 서비스에서 중복 갱신하지 않는다.
- 플래시카드는 CARD_OPENED, CARD_REVEALED 이벤트로 집계하며 응답·오답 해결 기록을 생성하지 않는다.

## 통계 계산

| 지표 | 원본과 계산 |
| --- | --- |
| 조회수·좋아요·저장 수 | content_metrics 뷰, 영구 캐시 없음 |
| 시청 완료율 | completed_at이 있는 watch_records / 모든 watch_records |
| 최초 영상 퀴즈 정답률 | first_video_responses의 CORRECT / 전체 행. 논리 문항별 첫 유효 정오 응답이며 SKIPPED 제외 |
| 맥락별 정답률 | 해당 context의 CORRECT / (CORRECT+WRONG). 반복 복습도 포함 |
| 참여율 | 실제 노출된 풀이 중 정오 응답이 있는 수 / 실제 노출된 풀이 수 |
| 건너뛰기 비율 | SKIPPED / (CORRECT+WRONG+SKIPPED) |
| 노출 없는 응답 | 별도 response_without_display_count. 정답률에는 포함, 참여율에서는 제외 |
| 무응답 노출 | 노출은 있으나 응답이 아직 없는 풀이 수. SKIPPED와 구분 |
| 현재 오답 | current_wrong_answers의 현재 공개 콘텐츠·최신 버전 미해결 상태 |
| 해결된 오답 수 | RESOLVED인 사용자·버전 행 수. 과거 버전도 포함하며 현재 오답과 같은 모집단의 비율로 계산하지 않음 |
| 카드 열람·정답 펼침 | 각 이벤트 수와 사용자 수를 각각 반환. 카드 세션 ID가 없어 펼침률은 임의로 계산하지 않음 |
| 과정 진행률 | 시청 완료 AND 논리 문항의 어느 버전이든 정답이 있는 단계 / 전체 편성 단계 |

DB 비율은 0~1이지만 현재 백엔드 응답 계약에 맞춰 percent는 0~100, 소수점 두 자리로 반환한다. 분모 0은 percent=null, 카운트는 0, 목록은 []이다.

과정 분모에는 비공개·영상 파일이 없는 단계도 남는다. 기존 구현과 뷰가 모두 시청 완료+정답을 요구하므로 퀴즈 없는 단계는 자동 완료되지 않는다. 이 정책을 바꾸려면 CRS 서비스와 DB 뷰를 함께 변경해야 한다.

대시보드 진행 중 과정은 시청 기록이 있는 미완료 과정 중 공개 단계가 있는 과정이다. SQL의 available_steps는 공개 상태 기준이고, 기존 CRS 상세의 available은 파일 존재도 검사한다. 실제 이용 가능 여부는 CRS 상세 응답을 따른다. 파일 유실은 DB 통계에서 별도 판정하지 않는다.

카테고리 현황은 공개 콘텐츠에 한정한다. NEEDS_REVIEW는 현재 오답 존재, NOT_STARTED는 해당 공개 콘텐츠에 시청·정오 응답 모두 없음, NO_CURRENT_ERRORS는 기록이 있으나 현재 오답 없음이다. NO_CURRENT_ERRORS를 숙달로 표시하지 않는다. 전체 대시보드 시청·응답 누계는 비공개 전환 후에도 보존된 본인 기록을 포함한다.

## 조회 일관성과 성능

대시보드 한 응답, 카테고리 한 응답, 콘텐츠 전체 통계 한 응답은 각각 단일 SQL 문으로 계산하여 세대·집계를 같은 문장 스냅샷에서 읽는다. 응답 목록의 total과 items도 하나의 SQL 문이다. 서로 다른 HTTP 요청까지 하나의 스냅샷을 보장하지는 않는다.

보기·태그·응답을 모두 한 번에 곱하는 조인 대신 원본별 집계를 사용한다. 목록은 LIMIT/OFFSET 및 고정 ID 보조 정렬을 사용한다. 데이터 규모를 재지 않고 새 캐시나 인덱스를 추가하지 않았다. 대시보드 과정 목록과 전체 통계는 대규모 데이터 부하 검증 후 최적화를 검토한다.

## DB 변경 검토 절차

1. 기능 담당자가 필요한 변경·기존 기록 영향·적용 및 복구 방법을 PR에 적는다.
2. 기존 head를 확인하고 새 revision을 작성한다. 공유된 0001은 수정하지 않는다.
3. 파트4가 키·제약·잠금 순서·기존 뷰 및 초기화 함수 영향을 검토한다.
4. 마이그레이션 PR은 순차 병합하고 다음 PR은 최신 head를 반영한다. alembic heads로 다중 head 여부를 확인한다.
5. 빈 DB 적용과 기존 자료 보존 테스트 후 팀원이 upgrade head로 반영한다.

파트1 라우터 등록 파일, 파트2 사용자·영상, 파트3 문항·응답 상세 파일은 이 작업에서 변경하지 않았다.
